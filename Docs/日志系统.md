# 日志系统设计文档

## 1. 概述

日志系统是 MapTools 项目的重要组成部分，基于模块化架构设计，用于记录系统运行状态、用户操作行为、轨迹匹配过程以及错误异常信息。系统采用分层日志架构，支持多级别、多输出、结构化日志记录，帮助开发人员快速定位问题并进行系统优化。

## 2. 系统架构

### 2.1 日志系统层次结构

```
日志系统 (LoggingSystem)
├── 核心日志器 (logger.py)          # 统一日志接口
├── 日志处理器 (handlers.py)        # 多种输出处理器
├── 日志配置管理                    # 动态配置管理
└── 日志分析工具                    # 日志查询和分析
```

### 2.2 模块化集成

- **BackendService**: 核心业务日志记录
- **MatchingAlgorithms**: 算法执行日志
- **DataModels**: 数据操作日志
- **ApiEndpoints**: API请求响应日志
- **AsyncTasks**: 异步任务执行日志
- **UtilityTools**: 工具函数调用日志
- **Tests**: 测试执行日志

## 3. 功能特性

### 3.1 核心功能

1. **多级别日志记录** (DEBUG/INFO/WARNING/ERROR/CRITICAL)
2. **结构化日志格式** (JSON格式，便于后续分析处理)
3. **多输出目标** (控制台、文件、数据库、远程服务)
4. **日志轮转功能** (按时间、大小、数量轮转)
5. **异常堆栈信息完整记录**
6. **性能影响最小化** (异步日志写入)
7. **日志过滤和搜索**
8. **实时日志监控**

### 3.2 测试日志
- 测试执行过程中会记录测试日志，便于调试测试失败原因
- 单元测试和集成测试分别记录到不同的日志文件中
- 测试日志包含测试用例执行时间、结果和错误信息

### 3.3 高级特性

- **分布式日志收集** (支持多服务实例)
- **日志压缩和归档**
- **敏感信息脱敏**
- **日志审计追踪**
- **性能指标统计**

## 4. 日志级别说明

| 级别 | 数值 | 用途 | 示例场景 |
|------|------|------|----------|
| **DEBUG** | 10 | 详细的调试信息 | 算法参数调试、数据流追踪 |
| **INFO** | 20 | 一般信息记录 | 用户操作、系统状态 |
| **WARNING** | 30 | 警告信息 | 数据异常、性能下降 |
| **ERROR** | 40 | 错误信息 | 业务逻辑错误、外部服务异常 |
| **CRITICAL** | 50 | 严重错误 | 系统崩溃、数据丢失 |

## 5. 日志格式规范

### 5.1 标准格式

``json
{
  "timestamp": "2025-09-16T18:30:45.123Z",
  "level": "INFO",
  "module": "MatchingAlgorithms.gotrackit_adapter",
  "function": "match_trajectory",
  "line": 45,
  "message": "开始执行轨迹匹配",
  "request_id": "req_123456789",
  "user_id": "user_001",
  "trajectory_id": "traj_001",
  "duration_ms": 1250,
  "extra": {
    "algorithm": "HMM",
    "points_count": 150,
    "road_network": "beijing_roads"
  }
}
```

### 5.2 错误日志格式

``json
{
  "timestamp": "2025-09-16T18:30:45.123Z",
  "level": "ERROR",
  "module": "DataModels.trajectory",
  "function": "save_trajectory",
  "line": 78,
  "message": "轨迹数据保存失败",
  "request_id": "req_123456789",
  "error_type": "DatabaseError",
  "error_code": "DB_CONNECTION_FAILED",
  "stack_trace": "Traceback (most recent call last)...",
  "extra": {
    "trajectory_id": "traj_001",
    "database_url": "mysql://***",
    "retry_count": 3
  }
}
```

## 6. 日志轮转策略

### 6.1 轮转规则

| 轮转类型 | 触发条件 | 保留策略 | 压缩策略 |
|----------|----------|----------|----------|
| **时间轮转** | 每天 00:00 | 保留 30 天 | 7天后压缩 |
| **大小轮转** | 文件 > 100MB | 保留 10 个文件 | 立即压缩 |
| **数量轮转** | 文件数 > 50 | 保留最新 30 个 | 立即压缩 |

### 6.2 日志文件命名

```
logs/
├── app/
│   ├── app_2025-09-16.log
│   ├── app_2025-09-16.log.1.gz
│   └── app_2025-09-15.log.2.gz
├── matching/
│   ├── matching_2025-09-16.log
│   └── matching_2025-09-15.log.1.gz
├── api/
│   ├── api_2025-09-16.log
│   └── api_2025-09-15.log.1.gz
└── error/
    ├── error_2025-09-16.log
    └── error_2025-09-15.log.1.gz
```

## 7. 配置管理

### 7.1 环境配置

```python
# 开发环境

LOGGING_FORMAT = "detailed"
LOG_TO_FILE = True
LOG_TO_CONSOLE = True

# 生产环境
LOGGING_LEVEL = "INFO"
LOGGING_FORMAT = "json"
LOG_TO_FILE = True
LOG_TO_CONSOLE = False
LOG_TO_DATABASE = True
```

### 7.2 模块配置

```python

        "level": "DEBUG",
```

### 8.2 内存管理

## 11. 集成方案

### 11.1 模块集成

```python
# 在各模块中使用日志
from LoggingSystem.logger import get_logger

logger = get_logger(__name__)

# 使用示例
logger.info("开始处理轨迹匹配请求", extra={
    "trajectory_id": trajectory_id,
    "algorithm": "HMM"
})

logger.error("轨迹匹配失败", exc_info=True, extra={
    "trajectory_id": trajectory_id,
    "error_code": "MATCHING_FAILED"
})
```

### 11.2 Docker 集成

```yaml
# docker-compose.yml 中的日志配置
services:
  backend:
    logging:
      driver: "json-file"
      options:
        max-size: "100m"
        max-file: "5"
    volumes:
      - ./Logs:/app/logs
```
