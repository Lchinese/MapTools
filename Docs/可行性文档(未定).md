## 一、系统概述

本系统旨在实现将 GPS 轨迹点序列智能匹配到道路网络上的功能，支持可视化展示与多算法融合。系统采用轻量级架构，兼顾当前快速验证需求与未来扩展能力。

### 核心功能
- ✅ 支持上传 `.gpx` / `.csv` 格式轨迹文件
- ✅ 基于天地图道路数据（Shapefile）进行路径匹配
- ✅ 使用 MySQL 存储与空间计算
- ✅ 集成 GoTrackIt 库实现基于改进隐马尔可夫模型（HMM）的地图匹配
- ✅ 支持多种匹配算法：最近邻匹配（Greedy）和 HMM 算法
- ✅ Web UI 展示原始轨迹与匹配结果
- ✅ 异步任务处理（通过 Redis + Celery）
- ✅ 使用 `uv` 管理 Python 依赖（现代替代 pip）
- ✅ 完整的日志记录系统

## 四、模块化架构设计

### 4.1 设计原则

本系统采用模块化设计，遵循以下核心原则：

- **单一职责原则**：每个模块只负责一个特定功能
- **开闭原则**：对扩展开放，对修改封闭
- **依赖倒置原则**：高层模块不依赖低层模块，都依赖于抽象
- **接口隔离原则**：使用多个专门的接口，而不是单一的总接口
- **松耦合高内聚**：模块间依赖最小化，模块内部功能高度相关

## 七、数据库初始化与数据导入

### 1. 进入 MySQL 容器并启用空间扩展

```bash
docker exec -it maptools-db-1 mysql -u gisuser -p gisdb
```

在 `mysql` 中执行：

```sql
-- MySQL 8.0 默认支持空间数据类型，无需额外扩展
-- 验证空间支持
SELECT ST_GeomFromText('POINT(116.3974 39.9093)') as test_point;
```

### 2. 导入天地图道路数据（Shapefile）

假设你已将天地图 ZIP 解压至 `./ExternalData/roads.shp`

```bash
# 使用 ogr2ogr 导入到 MySQL（在宿主机执行）
ogr2ogr -f "MySQL" MySQL:gisdb,host=localhost,port=3306,user=gisuser,password=mysecretpassword \
  ./ExternalData/roads.shp -nln roads -a_srs EPSG:4490 -t_srs EPSG:4490
```

> 🔍 注：`4490` 为 CGCS2000 坐标系，适用于中国地区天地图数据

### 3. 创建轨迹表

```sql
-- 创建轨迹元数据表
CREATE TABLE trajectories (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name TEXT,
    vehicle_id TEXT,
    upload_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 创建轨迹点表（带空间索引）
CREATE TABLE track_points (
    id INT AUTO_INCREMENT PRIMARY KEY,
    traj_id INT,
    time TIMESTAMP,
    geom POINT SRID 4490,
    speed FLOAT,
    FOREIGN KEY (traj_id) REFERENCES trajectories(id),
    SPATIAL INDEX idx_geom (geom)
);
```

## 八、核心流程设计

### 1. 轨迹上传与处理流程

```
graph TD
    A[用户上传 GPX/CSV] --> B{FastAPI 接收}
    B --> C[保存文件到 /UserUploads]
    C --> D[触发 Celery 异步任务]
    D --> E[Celery Worker 执行匹配]
    E --> F[调用 GoTrackIt HMM 算法匹配]
    F --> G[结果写入 MySQL]
    G --> H[更新 Redis 任务状态]
    H --> I[前端轮询获取结果]
    I --> J[Mapbox 展示匹配路径]
```

### 2. 核心算法：GoTrackIt HMM 地图匹配

- 通过概率图建模将 GPS 轨迹数据匹配到道路路网
- 支持路网生产与优化、轨迹生产、轨迹处理、地图匹配和时空可视化

## 九、GoTrackIt 库集成方案

### 9.1 GoTrackIt 库简介

GoTrackIt 是一个基于改进隐马尔可夫模型（HMM）的全流程地图匹配 Python 库，专门用于将车辆的 GPS 轨迹数据匹配到道路路网，获取标准化的时空轨迹。

### 9.2 核心功能模块

| 模块 | 功能描述 |
|------|----------|
| **路网生产与优化** | 处理道路网络数据，优化路网结构 |
| **轨迹生产** | 生成和处理 GPS 轨迹数据 |
| **轨迹处理** | 轨迹数据清洗、预处理和特征提取 |
| **地图匹配** | 基于 HMM 的智能轨迹匹配算法 |
| **时空可视化** | 轨迹和匹配结果的可视化展示 |

### 9.3 集成优势

- **专业算法**：基于隐马尔可夫模型的概率图建模，匹配精度高
- **全流程支持**：从轨迹预处理到最终匹配的完整解决方案
- **易于集成**：Python 原生库，与 FastAPI 无缝集成
- **可扩展性**：支持自定义参数和算法调优
- **生产就绪**：经过验证的工业级算法库

### 9.4 使用示例

```python
from gotrackit import MapMatcher, RoadNetwork, Trajectory

# 初始化地图匹配器
matcher = MapMatcher()

# 加载道路网络
road_network = RoadNetwork.from_shapefile("ExternalData/roads.shp")

# 加载轨迹数据
trajectory = Trajectory.from_gpx("UserUploads/track.gpx")

# 执行地图匹配
matched_trajectory = matcher.match(trajectory, road_network)

# 获取匹配结果
result_geojson = matched_trajectory.to_geojson()
```

### 9.5 与现有架构的集成

- **数据流**：轨迹文件 → GoTrackIt 处理 → MySQL 存储 → 前端展示
- **异步处理**：通过 Celery 异步调用 GoTrackIt 算法
- **结果存储**：匹配结果存储到 MySQL 空间数据库
- **API 接口**：FastAPI 提供统一的 RESTful 接口
