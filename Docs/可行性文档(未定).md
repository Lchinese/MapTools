> **版本：3.0**

## 一、系统概述

本系统旨在实现将 GPS 轨迹点序列智能匹配到道路网络上的功能，支持沿路网路径连接轨迹点，提供真实的路网轨迹展示。系统采用MongoDB数据库存储，支持分页查询和实时路网匹配。

### 核心功能（当前版本）
- ✅ 基于MongoDB数据库存储轨迹数据（`gps_points`、`original_trajectories`、`road_network`）
- ✅ 支持分页查询车辆轨迹数据（按车牌号分页）
- ✅ 路网数据：天地图 WFS 服务 + MongoDB持久化存储
- ✅ 轨迹匹配：GPS点吸附到最近道路节点
- 🔄 沿路网路径连接：同车牌时序相邻点间沿路网最短路径连接（将被天地图驾车规划API替代）
- ✅ 前端展示：React + Leaflet，支持原始轨迹与匹配轨迹切换
- ✅ 实时数据加载：从数据库动态加载轨迹数据
- ✅ 使用 `uv` 管理 Python 依赖
- ✅ 完整的日志记录系统
- ✅ 行政区划边界数据：本地GeoJSON文件 + MongoDB存储（已实现）
- ✅ 真实路径连接：天地图驾车规划API连接轨迹点（替代原有路网路径连接）

## 四、数据与存储策略（当前版本）
- **轨迹数据**：存储在MongoDB的`gps_points`集合，支持按车牌号分页查询
- **原始轨迹**：存储在`original_trajectories`集合，包含轨迹点序列和元数据
- **路网数据**：存储在`road_network`集合，从天地图WFS服务获取并持久化
- **行政区划数据**：存储在`administrative_areas`集合，从天地图行政区划API获取边界轮廓
- **路径数据**：存储在`trajectory_paths`集合，从天地图驾车规划API获取真实路径
- **匹配结果**：实时计算GPS点与路网的最短距离匹配
- **路径连接**：同车牌时序相邻点间使用真实道路路径连接


## 五、深圳市边界数据集成方案（已实现）

### 5.1 方案概述
使用本地GeoJSON文件存储深圳市行政区划边界数据，主要目的是**筛选出在深圳范围内的轨迹点，过滤掉不在深圳的点**，确保轨迹数据的地理范围准确性。

### 5.2 数据源说明
- **数据格式**：GeoJSON格式的深圳市边界文件
- **坐标系统**：EPSG::4490（中国大地坐标系2000）
- **几何类型**：MultiPolygon（包含2个多边形的复杂边界）
- **行政区划信息**：
  - 名称：深圳市
  - 编码：156440300
  - 级别：3（地级市）

### 5.3 数据文件结构
```json
{
    "type": "FeatureCollection",
    "features": [{
        "type": "Feature",
        "geometry": {
            "type": "MultiPolygon",
            "coordinates": [[[边界坐标点序列]]]
        },
        "properties": {
            "name": "深圳市",
            "gb": "156440300"
        }
    }],
    "crs": {
        "type": "name",
        "properties": {
            "name": "urn:ogc:def:crs:EPSG::4490"

### 5.4 实现优势
1. **无需API权限**：避免天地图API权限配置问题
2. **数据稳定**：本地文件不受网络影响
3. **性能优异**：直接读取本地文件，响应速度快
4. **维护简单**：数据更新只需替换文件即可

class ShenzhenBoundaryService:
    """深圳市边界数据服务"""
    
    def __init__(self, mongodb_url: str, database_name: str):
        self.mongodb_url = mongodb_url
        self.database_name = database_name
        self.db_client = None
        self.db = None
        self.areas_collection = None
    
    async def get_shenzhen_boundary(self) -> Dict:
        """获取深圳市行政区划边界数据（从本地GeoJSON文件）"""
        # 读取本地GeoJSON文件
        geojson_path = r"c:\Users\86187\Downloads\深圳市_市.geojson"
        
        with open(geojson_path, 'r', encoding='utf-8') as f:
            geojson_data = json.load(f)
        
        # 转换为API响应格式
        feature = geojson_data['features'][0]
        properties = feature['properties']
        geometry = feature['geometry']
        
        # 计算中心点
        coordinates = geometry['coordinates'][0][0]
        lng_sum = sum(coord[0] for coord in coordinates)
        lat_sum = sum(coord[1] for coord in coordinates)
        center_lng = lng_sum / len(coordinates)
        center_lat = lat_sum / len(coordinates)
        
        return {
            "status": 200,
            "data": {
                "district": [{
                    "gb": properties['gb'],
                    "name": properties['name'],
                    "level": 3,
                    "center": {"lng": center_lng, "lat": center_lat},
                    "boundary": geometry
                }]
            }
        }
    
    def filter_trajectory_points(self, points: List[Dict]) -> List[Dict]:
        """筛选在深圳范围内的轨迹点"""
        # 从MongoDB获取深圳市边界
        shenzhen_boundary = self.areas_collection.find_one({"gb_code": "156440300"})
        
        if not shenzhen_boundary:
            raise Exception("深圳市边界数据未找到")
        
        # 使用shapely进行点是否在多边形内的判断
        boundary_geom = MultiPolygon([
            Polygon(coords) for coords in shenzhen_boundary["boundary"]["coordinates"]
        ])
        
        filtered_points = []
        for point in points:
            point_geom = Point(point["lng"], point["lat"])
            if boundary_geom.contains(point_geom):
                filtered_points.append(point)
        
        return filtered_points
    
    def is_point_in_shenzhen(self, lng: float, lat: float) -> bool:
        """判断点是否在深圳范围内"""
        shenzhen_boundary = self.areas_collection.find_one({"gb_code": "156440300"})
        if not shenzhen_boundary:
            return False
        
        boundary_geom = MultiPolygon([
            Polygon(coords) for coords in shenzhen_boundary["boundary"]["coordinates"]
        ])
        point_geom = Point(lng, lat)
        return boundary_geom.contains(point_geom)
```

## 六、天地图驾车规划API集成方案

### 6.1 API概述
天地图驾车规划API用于连接时序相邻的两个**匹配后的轨迹点**，通过真实的道路路径替代简单的直线连接，提供更符合实际行驶路径的轨迹可视化效果。

**重要说明**：
- 输入：时序相邻的**匹配后轨迹点**（已通过道路匹配算法处理）
- 输出：连接这两个轨迹点的**真实道路路径**（固定使用最快路线）
- 目的：替代直线连接，提供更准确的轨迹可视化
- 路线选择：固定使用最快路线（style="0"），无需考虑其他路线选项
- 不是用于：原始GPS点之间的路径规划

### 6.2 API接口规范
```
请求URL: http://api.tianditu.gov.cn/drive
请求方法: GET
```

#### 请求参数
| 参数名 | 必选 | 类型 | 说明 | 默认值 |
|--------|------|------|------|--------|
| postStr | 是 | string | JSON格式的路径规划参数 | 无 |
| type | 是 | string | 固定值"search" | search |
| tk | 是 | string | 天地图API密钥 | 无 |

#### postStr参数说明
```json
{
    "orig": "起点经纬度",
    "dest": "终点经纬度", 
    "mid": "途径点经纬度字符串",
    "style": "导航路线类型"
}
```

| 参数名 | 必选 | 类型 | 说明 | 默认值 |
|--------|------|------|------|--------|
| orig | 是 | string | 起点经纬度 | 格式：lng,lat |
| dest | 是 | string | 终点经纬度 | 格式：lng,lat |
| mid | 否 | string | 途径点经纬度 | 格式：lng1,lat1;lng2,lat2 |
| style | 否 | string | 导航路线类型 | 0（最快路线） |

#### 6.3.2 匹配轨迹点连接策略
```python
class MatchedTrajectoryPathConnector:
    """匹配轨迹点路径连接器"""
    
    def __init__(self, api_key: str, db_client):
        self.api_key = api_key
        self.base_url = "http://api.tianditu.gov.cn/drive"
        self.db = db_client
        self.paths_collection = self.db.trajectory_paths
    
    async def connect_matched_trajectory_points(self, matched_points: List[Dict]) -> List[Dict]:
        """使用驾车规划API连接时序相邻的匹配轨迹点并存储到MongoDB"""
        connected_segments = []
    
    for i in range(len(matched_points) - 1):
            start_point = matched_points[i]  # 匹配后的轨迹点
            end_point = matched_points[i + 1]  # 匹配后的轨迹点
            
            # 生成路径唯一标识
            path_id = self.generate_path_id(start_point, end_point)
            
            # 先检查MongoDB中是否已存在该路径
            existing_path = await self.get_cached_path(path_id)
            if existing_path:
                connected_segments.append(existing_path)
                continue
            
            # 调用驾车规划API获取真实路径（固定使用最快路线）
            route_data = await self.get_driving_route(
                orig=f"{start_point['lng']},{start_point['lat']}",
                dest=f"{end_point['lng']},{end_point['lat']}"
            )
            
            if route_data:
                # 解析路径数据
                path_coords = self.parse_route_coordinates(route_data)
                path_doc = {
                    "path_id": path_id,
                    "start_point": start_point,
                    "end_point": end_point,
                    "path_coordinates": path_coords,
                    "distance": route_data.get('distance', 0),
                    "duration": route_data.get('duration', 0),
                    "created_at": datetime.now(),
                    "updated_at": datetime.now()
                }
                
                # 存储到MongoDB
                await self.save_path_to_mongodb(path_doc)
                connected_segments.append(path_doc)
        
        return connected_segments
    
    def generate_path_id(self, start_point: Dict, end_point: Dict) -> str:
        """生成路径唯一标识"""
        start_coords = f"{start_point['lng']:.6f},{start_point['lat']:.6f}"
        end_coords = f"{end_point['lng']:.6f},{end_point['lat']:.6f}"
        return hashlib.md5(f"{start_coords}-{end_coords}".encode()).hexdigest()
    
    async def get_cached_path(self, path_id: str) -> Optional[Dict]:
        """从MongoDB获取缓存的路径"""
        return await self.paths_collection.find_one({"path_id": path_id})
    
    async def save_path_to_mongodb(self, path_doc: Dict) -> str:
        """保存路径数据到MongoDB"""
        result = await self.paths_collection.insert_one(path_doc)
        return str(result.inserted_id)
    
    async def get_driving_route(self, orig: str, dest: str) -> Dict:
        """获取驾车路径规划（固定使用最快路线）"""
        post_str = json.dumps({
            "orig": orig,
            "dest": dest,
            "style": "0"  # 固定使用最快路线
        })
        
        params = {
            "postStr": post_str,
            "type": "search",
            "tk": self.api_key
        }
        
        async with httpx.AsyncClient() as client:
            response = await client.get(self.base_url, params=params)
            return self.parse_xml_response(response.text)
    
    def parse_route_coordinates(self, route_data: Dict) -> List[List[float]]:
        """解析路径坐标"""
        # 解析routelatlon字段获取路径坐标
        coords_str = route_data.get('routelatlon', '')
        coordinates = []
        
        if coords_str:
            # 解析坐标字符串格式：lng1,lat1;lng2,lat2;...
            coord_pairs = coords_str.split(';')
            for pair in coord_pairs:
                if ',' in pair:
                    lng, lat = pair.split(',')
                    coordinates.append([float(lng), float(lat)])
        
        return coordinates
```

- 天地图 WFS：用于道路匹配分析，需密钥与遵守天地图服务条款

## 七、优化与风险
- **路网图构建**：大型路网图构建耗时，采用增量更新和缓存策略
- **路径计算**：最短路径算法复杂度高，使用A*算法优化
- **内存占用**：路网图占用内存较大，考虑分区域加载
- **实时性**：路径计算可能影响响应速度，采用异步计算和缓存

## 九、总结

当前版本采用"MongoDB数据库驱动 + 真实路径连接 + 本地边界数据"策略，实现高精度的轨迹展示。通过天地图驾车规划API连接轨迹点，获得真实道路路径，替代原有的路网图算法，提供更符合实际行驶路径的轨迹可视化效果。

**功能升级说明**：
1. **路径连接方案升级**：从原有的NetworkX图算法完全升级为天地图驾车规划API，获得更准确的真实道路路径
2. **行政区划数据集成**：使用本地GeoJSON文件方案，避免API权限问题，实现轨迹区域分析、边界可视化和数据过滤等功能
3. **性能优化**：通过路径缓存、批量处理、异步调用等方式优化API使用效率
4. **数据稳定性**：本地文件方案提供更稳定的数据源，不受网络和API权限影响

**已实现功能**：
- ✅ MongoDB数据库存储轨迹数据
- ✅ 本地GeoJSON文件边界数据集成
- ✅ 轨迹点筛选和区域分析
- ✅ 真实路径连接算法
- ✅ 完整的测试和验证功能

这些升级将显著提升系统的轨迹展示精度和地理信息分析能力。
