# **轨迹路径匹配系统可行性技术文档**
> **版本：2.3**
> **编制团队：2人开发 + AI Agent 协助**
> **目标**：构建一个可验证、易扩展、支持多算法演进的轨迹地图匹配系统

---

## 一、系统概述

本系统旨在实现将 GPS 轨迹点序列智能匹配到道路网络上的功能，支持可视化展示与多算法融合。系统采用轻量级架构，兼顾当前快速验证需求与未来扩展能力。

### 核心功能（当前版本约束）
- ✅ 支持上传多种格式轨迹文件（`.gpx` / `.csv` / `.txt`）
- ✅ 使用出租车GPS数据（日期,时间,类型,车牌号,经度,纬度,速度,方向,状态）
- ✅ 前端底图：天地图 WMTS `vec_w`（仅展示，栅格切片）
- ✅ 路网数据：OpenStreetMap（用于匹配与统计的矢量/中心线）
- ✅ 数据来源：直接读取项目本地 `data/` 目录，不做入库
- ✅ 数据库用途：仅保留用户认证相关表 `users`
- ✅ 集成 GoTrackIt（HMM）与 Greedy 两类匹配算法
- ✅ Web UI 展示原始轨迹与匹配结果
- ✅ 异步任务处理（通过 Redis + Celery）
- ✅ 使用 `uv` 管理 Python 依赖（现代替代 pip）
- ✅ 完整的日志记录系统

---

## 二、技术栈选型说明

| 模块 | 技术 | 选型理由 |
|------|------|----------|
| **前端** | React + Leaflet (react-leaflet) | 与天地图 WMTS 易集成，亦可切换 OSM 瓦片 |
| **后端** | FastAPI (Python) | 快速构建 API，自动生成文档，异步支持好 |
| **缓存/消息队列** | Redis | 异步任务与缓存 |
| **算法引擎** | Python (Shapely, GeoPandas, GoTrackIt) | 易于实现与替换 |
| **底图服务** | 天地图 WMTS vec_w | 国内可用的展示底图（栅格） |
| **路网数据** | OpenStreetMap | 开放可计算的矢量/路网 |
| **依赖管理** | `uv` | 更快的 Python 包管理 |
| **部署** | Docker Compose | 一键多服务 |

---

## 四、数据与存储策略（当前版本）
- 轨迹/刷卡/路网：直接从 `data/` 读取（TXT/CSV/GeoJSON/PBF 等），不写入数据库。
- 数据库：仅保留 `users` 表用于认证；不创建轨迹/路网等业务表。
- 说明：后续如需性能与检索能力，可逐步引入 PostGIS/Parquet 缓存，但本版本不启用。

---

## 五、许可与合规
- 天地图 WMTS：仅展示用途，需密钥与遵守条款。
- OSM 矢量：遵循 ODbL 许可，保留署名 “© OpenStreetMap contributors”。

---

## 六、优化与风险
- 本地数据体量大：采用分块读取与流式处理。
- 首次解析 OSM PBF：离线缓存解析结果（GeoPackage/Parquet），但本版本不强制。
- 底图限流：可配置备用底图或本地缓存。

---

## 七、总结

当前版本采用“本地文件驱动 + 极简数据库（仅用户）”策略，降低上手成本，加速验证匹配链路；后续可按需扩展为数据库驱动与空间索引加速。
